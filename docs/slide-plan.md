# Slide Plan — deck as code, not deck as artifact

> **Why a plan before slides.** Free-form slide generation (Claude Code
> emitting pptx/design files, or ad-hoc Canva sessions) reliably produces the
> failure modes we've hit before: overlapping images and text blocks, stale
> designs that drift from the product, theme inconsistency, and heavy token
> burn on layout fiddling. The fix is the same philosophy as
> `datasets.lock.json`: **the deck is generated from committed source, and
> layout is constrained by a theme, not hand-positioned.**

## Tooling decision

**Recommended: Marp** (`marp-cli`, markdown → HTML/PDF/pptx).

| Failure mode we've hit | How deck-as-code prevents it |
|---|---|
| Overlapping text/images | Marp layouts are flow-based — elements cannot overlap; content that doesn't fit is a visible overflow you fix by cutting words, not by nudging boxes |
| Theme inconsistency | One committed CSS theme (Warm Human tokens: terracotta primary, warm neutrals, humanist sans) applied to every slide by the compiler — a slide *cannot* be off-theme |
| Stale designs | Deck source lives in `docs/slides/deck.md`; screenshots and diagrams are regenerated by script from the running product — regenerate = current |
| No proper diagrams | Mermaid sources committed next to the deck, pre-rendered to SVG via `mmdc` (mermaid-cli) in the build step — crisp at projector resolution, consistent fonts |
| Token burn | Claude writes/edits **markdown text only** — the compiler does 100 % of layout. No image generation, no pixel pushing |

Alternatives considered: Canva/Gamma (fast but hand-layout → overlap + drift,
not version-controlled), claude.ai artifacts → pptx (token-heavy layout
iteration — the exact concern), Figma (right for the product UI, wrong for a
12-slide deck under time pressure).

Build (once tooling is installed):

```bash
npx @marp-team/marp-cli docs/slides/deck.md --theme docs/slides/warm-human.css -o deck.pdf
npx @mermaid-js/mermaid-cli -i docs/slides/diagrams/*.mmd -o docs/slides/assets/
```

## Narrative spine (12 slides)

Source of truth for every claim: [[solution-overview]] (judge-facing) — the
deck is a compression of that page, never a fork of it.

1. **Title** — product name + one-liner: "The morning triage for One Care
   caseworkers."
2. **The problem** — JSGP statement; the reactive-tools gap (button fails
   when unconscious). One statistic, one sentence of human stakes (long lie).
3. **The insight** — the home already knows. Routine is a vital sign;
   absence of motion is data. Nobody has to press anything.
4. **The product** *(screenshot)* — the ranked caseload, calm by default.
5. **The beat** *(screenshot pair)* — fall fires → pins to top with a
   plain-language reason and a recommended action.
6. **How it works** *(mermaid, the 3-layer diagram)* — sense → score →
   decide. One line per layer; no internals.
7. **Explainable by contract** *(screenshot: drill-down)* — every number
   decomposes; the caseworker stays in charge.
8. **It's real** — 96.2 % detection on 1,798 real falls; the per-activity
   false-alarm story; 220 days of a real home driving the chronic track.
   (Our strongest differentiator vs. concept decks — lead with it.)
9. **Built for Singapore** — self-baselining = no imported prior; per-HDB
   deployment; presence-only dignity; multiplies One Care's existing people.
10. **Honest limits** — the scoring-card slide. Judges trust teams that
    state limitations unprompted.
11. **Beyond the PoC** — two-sided anomaly, escalation integrations, pilot
    design (one cluster, measurable: time-to-detection, minutes saved).
12. **Ask + team** — what we'd need to pilot.

Rule of thumb per slide: ≤ 30 words of body text, one visual. If a slide
needs more words, the words belong in the demo narration, not on screen.

## Process guardrails

- Deck compiles clean or the change doesn't land (same bar as tests).
- Screenshots are **regenerated, never edited** — if a screenshot looks
  wrong, fix the product, not the pixels.
- Every number on a slide must exist in [[solution-overview]] or
  [[scoring-card]] — no deck-only claims.
- Theme CSS is the only place visual identity lives; slide source contains
  zero inline styling.
